# ФинВыбор — maeb-fin.ru

Витрина финансовых продуктов клиента (Nester). Статика, никакого бэкенда:
сайт лежит на GitHub Pages в репозитории `Daviddavidso/nester-pp`, домен
подключён файлом `CNAME`.

## Что где лежит

| Файл | Зачем |
|---|---|
| `index.html` | Каркас страницы. Тексты и карточки в него вставляет скрипт. |
| `data.js` | **Единственный файл с содержимым**: категории, офферы, тексты, подвал. |
| `script.js` | Движок витрины: каталог, фильтры, вопросы, строка партнёров. |
| `styles.css` | Оформление сайта. |
| `admin.html` + `admin.js` + `admin.css` | Админка для клиента. |
| `publish.js` | Блок «Сохранить на сайт» в админке. |
| `logos/` | Логотипы банков и МФО (44 файла). |
| `fonts/` | Шрифты локально, без обращений к Google. |
| `publish-server/` | Сервис публикации для Vercel. Пока не развёрнут, см. ниже. |

## Категории

По просьбе клиента кнопки «Все офферы» на сайте нет: при открытии сразу
выбраны **дебетовые карты**, дальше идут кредитные, РКО и деньги до зарплаты.
Порядок кнопок задаётся порядком строк в `CATEGORIES` в `data.js`.

Строка `{ id: 'all', … }` в `data.js` осталась намеренно: на сайт она не
попадает, её использует только админка — там это переключатель «показать
весь каталог», а не категория товара.

## Админка

**Адрес:** `maeb-fin.ru/admin.html` — пароль лежит в `~/АДМИНКИ.md`.

Пароль проверяется в браузере: в исходнике только `sha256(соль + пароль)`,
тот же хеш продублирован в файле `.admin-pass`. Это заслон от случайного
захода, а не защита: каталог витрины и так открыт всем. Сменить пароль —
пересчитать хеш и записать его в `admin.html` (`PASS_SHA`) и в `.admin-pass`:

```bash
python3 -c "import hashlib;print(hashlib.sha256(('maeb-v1-3c36f8'+'НОВЫЙ-ПАРОЛЬ').encode()).hexdigest())"
```

Что умеет: офферы по категориям (добавить, изменить, удалить, свой логотип
файлом или ссылкой), все тексты страницы, вопросы и ответы, подвал.

Правки клиента сразу видны **на его собственном экране** — сайт подхватывает
их из браузера и показывает сверху плашку «Показаны правки из админки».
Посетители до публикации видят прежнюю версию.

## Как правки попадают на сайт

Сейчас: клиент нажимает «Сохранить на сайт», браузер скачивает `data.js`,
клиент присылает файл. Дальше:

```bash
cp ~/Downloads/data.js ~/nester-pp/data.js
bash deploy.sh "Каталог от клиента"
```

GitHub Pages пересобирает страницу за 1–3 минуты.

### Чтобы клиент публиковал сам (10 минут работы)

PHP на GitHub Pages нет, поэтому публикация идёт через маленький сервис на
Vercel — код лежит в `publish-server/`, он уже настроен на этот репозиторий
и домен. Что нужно сделать:

1. GitHub → Settings → Developer settings → Fine-grained tokens: создать токен
   **только** на репозиторий `Daviddavidso/nester-pp`, право
   **Contents: Read and write**.
2. Развернуть `publish-server/` на Vercel проектом с именем **maeb-publish**
   (адрес `https://maeb-publish.vercel.app/api/publish` уже прописан в
   `admin.html`).
3. В Settings → Environment Variables добавить `GH_TOKEN` с этим токеном
   и нажать Redeploy.

После этого кнопки «Сохранить на сайт» и «Вернуть предыдущую версию» в
админке начинают работать сами — менять код не нужно. Правка появляется на
сайте через минуту-другую: столько собирается Pages.

## Что стоит доделать до запуска трафика

- **Ссылки.** В `data.js` стоят адреса официальных сайтов банков и МФО.
  Перед трафиком заменить на партнёрские (поле `url` или админка).
- **Цифры.** Ставки, лимиты и суммы заполнены типовыми значениями из
  публичной рекламы. Сверить с личным кабинетом партнёрки: несовпадение —
  это недостоверная реклама, и спросят с владельца сайта.
- **`noindex`.** В `index.html` стоит `<meta name="robots" content="noindex, nofollow">`:
  пока в карточках нет наименования рекламодателя и ИНН, маркировка рекламы
  неполная. Появятся реквизиты — строку удалить, сайт откроется поисковикам.
