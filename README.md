# ФинВыбор — maeb-fin.ru

Витрина финансовых продуктов клиента (Nester). Статика, без своего сервера:
сайт лежит на GitHub Pages в репозитории `Daviddavidso/nester-pp`, домен
подключён файлом `CNAME`.

## Что где лежит

| Файл | Зачем |
|---|---|
| `index.html` | Каркас страницы. Тексты и карточки в него вставляет скрипт. |
| `data.js` | **Единственный файл с содержимым**: категории, офферы, тексты, подвал. Его правит клиент из админки. |
| `script.js` | Движок витрины: каталог, фильтры, вопросы, строка партнёров. |
| `draft.js` | Черновик правок из админки: когда показывать его хозяину сайта, когда он уже на сайте и не нужен. Общий для сайта и админки. |
| `styles.css` | Оформление сайта. |
| `admin.html` + `admin.js` + `admin.css` | Админка для клиента. |
| `publish.js` | «Сохранить на сайт»: кладёт `data.js` в репозиторий через GitHub API. |
| `publish-key.js` | Токен GitHub для сохранения, зашифрованный паролем админки. |
| `tools/publish-key.mjs` | Собирает `publish-key.js`: токен, смена пароля, проверка. |
| `.pass-note` | Пароль админки. **Только локально**, в git не попадает. |
| `logos/` | Логотипы банков и МФО. |
| `fonts/` | Шрифты локально, без обращений к Google. |

## Категории

По просьбе клиента кнопки «Все офферы» на сайте нет: при открытии сразу
выбраны **дебетовые карты**, дальше идут кредитные, РКО и деньги до зарплаты.
Порядок кнопок задаётся порядком строк в `CATEGORIES` в `data.js`.

Строка `{ id: 'all', … }` в `data.js` осталась намеренно: на сайт она не
попадает, её использует только админка — там это переключатель «показать
весь каталог», а не категория товара.

## Админка

**Адрес:** `https://maeb-fin.ru/admin.html`, пароль — в `.pass-note`
(и в `~/АДМИНКИ.md`).

Что умеет: офферы по категориям (добавить, изменить, удалить, свой логотип
файлом или ссылкой), все тексты страницы, вопросы и ответы, подвал;
«Сохранить на сайт», «Вернуть предыдущую версию», «Скачать сайт целиком»,
копия `data.js` и сброс несохранённых правок.

Правки сразу видны **на экране у клиента** — сайт в его браузере показывает
черновик и плашку «Это ваши правки из админки — посетители их пока не видят»
(кнопка «Посмотреть как посетитель» ничего не удаляет). После «Сохранить на
сайт» плашка становится зелёной «сохранены, сайт обновляется», а когда
сайт обновился, черновик убирается сам.

## Как правки попадают на сайт

Клиент жмёт «Сохранить на сайт» → `publish.js` коммитит `data.js` в ветку
`main` через GitHub API → GitHub Pages пересобирает сайт (обычно 1–2 минуты)
→ админка сама проверяет живой `data.js` и пишет «Готово — правки на сайте».
«Вернуть предыдущую версию» кладёт на сайт `data.js` из предыдущего коммита.

Посетители получают свежий каталог: `index.html` подгружает `data.js` с
меткой, меняющейся раз в минуту, — браузерный кеш Pages (10 минут) не мешает.

### Ключ сохранения

Админке нужен **fine-grained токен GitHub только на репозиторий
`Daviddavidso/nester-pp`**, право **Contents: Read and write**. Он лежит в
`publish-key.js`, зашифрованный паролем админки (PBKDF2-SHA256 600 000
итераций + AES-GCM). Пароль одновременно открывает админку и расшифровывает
токен: в исходниках нет ни пароля, ни быстрого хеша, который можно перебрать.

Создать токен (ссылка уже заполнена, остаётся выбрать репозиторий
`nester-pp` в «Only select repositories» и нажать Generate):

https://github.com/settings/personal-access-tokens/new?name=maeb-fin+admin&description=%D0%A1%D0%BE%D1%85%D1%80%D0%B0%D0%BD%D0%B5%D0%BD%D0%B8%D0%B5+%D0%BA%D0%B0%D1%82%D0%B0%D0%BB%D0%BE%D0%B3%D0%B0+%D0%B8%D0%B7+%D0%B0%D0%B4%D0%BC%D0%B8%D0%BD%D0%BA%D0%B8+maeb-fin.ru&target_name=Daviddavidso&expires_in=none&contents=write

Потом:

```bash
node tools/publish-key.mjs token      # вставить токен (ввод скрыт), он проверится на GitHub
bash deploy.sh "Ключ сохранения на сайт"
```

Другие команды:

```bash
node tools/publish-key.mjs check      # рабочий ли ключ и когда истекает
node tools/publish-key.mjs password   # сменить пароль админки (токен сохранится)
```

Если токен истёк или его отозвали, админка не ломается: кнопка
превращается в «Скачать файл с правками», клиент присылает файл, а дальше
`cp ~/Downloads/data.js data.js && bash deploy.sh "Каталог от клиента"`.

## Выкладка

`bash deploy.sh "что поменяли"` — коммит и пуш (обычный `git push` в этом
окружении виснет, скрипт берёт ключи у `gh`). **Перед выкладкой
`git pull --rebase`**: клиент сам коммитит `data.js` из админки.

## Что стоит доделать до запуска трафика

- **Ссылки.** Часть офферов клиент уже перевёл на партнёрские ссылки
  (с erid), у остальных — официальные сайты банков и МФО.
- **Цифры.** Ставки, лимиты и суммы заполнены типовыми значениями из
  публичной рекламы. Сверить с личным кабинетом партнёрки: несовпадение —
  это недостоверная реклама, и спросят с владельца сайта.
- **`noindex`.** В `index.html` стоит `<meta name="robots" content="noindex, nofollow">`:
  пока в карточках нет наименования рекламодателя и ИНН, маркировка рекламы
  неполная. Появятся реквизиты — строку удалить, сайт откроется поисковикам.
